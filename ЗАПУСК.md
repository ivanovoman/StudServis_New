# Как запустить у себя

Нужны **два** сервера, оба работают одновременно:

- **Node** — раздаёт сайт и генерацию текста (порт 3000)
- **Python** — загрузка файлов, чтение PDF, поиск источников (порт 8000)

Без Python сайт откроется, но кнопка «Настройки» не сможет принимать
файлы.

## Что поставить заранее

- **Node.js 18+** — https://nodejs.org (обычный установщик, «Next → Next»)
- **Python 3.11+** — https://python.org
  При установке на Windows обязательно отметить галочку
  **«Add Python to PATH»**, иначе команды ниже не найдутся.

Проверка:

```
node -v
python --version
```

Если `python` не найден, попробуйте `py --version` — на Windows часто
работает именно так, и тогда во всех командах ниже пишите `py` вместо
`python`.

## Шаг 1. Скачать код

```
git clone -b devin/1786964976-backend-integration https://github.com/ivanovoman/StudServis_New
cd StudServis_New
```

Без git: на странице репозитория зелёная кнопка **Code → Download ZIP**,
затем распаковать и зайти в папку.

## Шаг 2. Зависимости

```
npm install
pip install -r backend/requirements.txt
```

Займёт пару минут. Python-пакетов примерно на 100 МБ.

Файл `backend/requirements-future.txt` ставить **не нужно** — там
зависимости модулей, которые ещё не написаны (Qdrant, Celery, ЮKassa).
Один из них тянет torch на два гигабайта.

## Хранение работ

Работы сохраняются сами, по частям, прямо во время сборки. Если закрыть
вкладку на середине — написанное останется.

Открыть сохранённое: кнопка **«Мои работы»** рядом с «Настройками
работы». Там же можно скачать DOCX или удалить работу.

Где лежит. По умолчанию — файл SQLite `backend/storage/works.db`.
Отдельную СУБД ставить не нужно. Для боевого сервера задайте переменную
`DATABASE_URL`, и всё переедет на PostgreSQL без правки кода:

```
DATABASE_URL=postgresql+asyncpg://user:пароль@localhost:5432/studservis
```

Чьи это работы. Пока входа по паролю нет, работы привязаны к браузеру:
при первом открытии он заводит себе случайный ключ и хранит его у себя.
Поэтому на другом компьютере (и в режиме инкогнито) список будет пустым.
Когда появится вход, работы привяжутся к учётной записи.

Хранение необязательно: если Python-бэкенд не запущен, генерация
работает как прежде, просто без сохранения.

## Ключ OpenAlex (необязательно, но желательно)

Источники подбираются из двух баз: КиберЛенинка и OpenAlex. Первая
работает без всяких ключей. Вторая с февраля 2026 требует ключ: анонимам
там оставили около сотни запросов в сутки **на всех сразу**, поэтому без
ключа она чаще всего отвечает отказом, и в выдаче остаются одни
русскоязычные статьи.

Ключ бесплатный и делается за минуту: аккаунт на `openalex.org`, затем
`openalex.org/settings/api`. Скопируйте его в `.env`:

```
OPENALEX_API_KEY=ваш_ключ
```

Без ключа сервис работает — просто без зарубежных публикаций. Отказ
базы виден в логе Python-бэкенда строкой «OpenAlex не ответил»: раньше
он проходил молча и выглядел так, будто по теме ничего не написано.

## Проверка ссылок на закон

Во время сборки каждая написанная часть сверяется с оглавлениями
кодексов на consultant.ru: модель охотно выдумывает номера статей, и
заметить это на глаз почти невозможно.

Под заголовком раздела появляются пометки двух видов: красная «Ссылки на
закон не сходятся» — номер неверен, статьи нет или она утратила силу
(если подходящая статья нашлась, её номер называется); серая «Сверить не
удалось, взгляните сами» — текст пересказал статью своими словами.

Работает через тот же Python-бэкенд. Не запущен — сверка молча
пропускается, сборка идёт как обычно.

## Шаг 3. Ключ модели

Скопировать `.env.example` в `.env`:

```
copy .env.example .env        (Windows)
cp .env.example .env          (Linux / macOS)
```

Открыть `.env` блокнотом и вписать ключ **одного** из поставщиков.

Вариант А — GigaChat от Сбера. Рекомендуется: работает из России без
VPN, 365 млн бесплатных токенов на год, заметно быстрее OpenRouter
(15 секунд против 113 на одном и том же введении) и не выдумывает
номера статей.

```
LLM_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=строка_base64_из_личного_кабинета
```

Ключ берётся на https://developers.sber.ru/studio — создать проект
GigaChat API, раздел «Настройки API», кнопка «Получить ключ». Копировать
надо **Authorization Key** (длинная строка Base64, ~100 символов), а не
Client Secret — иначе будет ошибка 401.

Сертификат Минцифры, без которого Сбер не отвечает, уже лежит в
`certs/` и подключается сам. Настраивать ничего не нужно.

Проверить ключ, не раскрывая его:

```
npm run check:gigachat
```

Команда напечатает список доступных моделей, а сам ключ покажет только
как `MDFh...Mw==`. Вывод можно спокойно кому-то переслать.

Вариант Б — OpenRouter (из России нужен VPN, бесплатно 50 запросов в
сутки):

```
LLM_PROVIDER=openrouter
OPENROUTER_API_KEY=sk-or-v1-...
```

Ключ берётся на https://openrouter.ai/keys

Лучше указать оба сразу: при отказе первого сервер сам перейдёт ко
второму, и работа не прервётся на середине.

```
LLM_PROVIDER=gigachat
LLM_FALLBACK_PROVIDER=openrouter
```

Подробно про ключи — где взять, что именно копировать и сколько дают
бесплатно — в файле **`КЛЮЧИ.md`**. Техническое сравнение поставщиков —
`docs/LLM_PROVIDERS.md`.

Без ключа сайт откроется и файлы будут загружаться, но генерация текста
работать не будет.

## Шаг 4. Запуск

Нужны **два окна терминала**. Оба остаются открытыми, пока вы работаете.

**Окно 1 — Python:**

```
cd backend
python -m uvicorn app.main:app --port 8000
```

Признак успеха: `Application startup complete.`

**Окно 2 — Node** (из корня проекта):

```
npm start
```

Признак успеха: `Студсервис запущен на http://localhost:3000`

## Шаг 5. Открыть

**http://localhost:3000**

Тема оформления выбирается случайно при каждом заходе. Открыть
конкретную:

```
http://localhost:3000/?theme=Windows_95.html
http://localhost:3000/?theme=Green_Phosphor.html
http://localhost:3000/?theme=amber-crt.html
http://localhost:3000/?theme=ZX_Spectrum_Style_UI.html
```

Все 16 тем — в папке `public/themes/`.

## Как обновиться до свежей версии

Если проект уже скачан и вы хотите забрать последние правки.

### Вариант А. Скачивали через git clone

В папке проекта:

```
git pull
```

Всё. Ваш `.env` с ключом не тронется — он в `.gitignore` и git его не
трогает.

Если pull ругается `Your local changes would be overwritten` — значит вы
что-то правили в файлах проекта. Чтобы отбросить свои правки и взять
версию с GitHub:

```
git checkout -- .
git pull
```

### Вариант Б. Скачивали ZIP

`git pull` не сработает: в ZIP нет истории git. Проще перейти на клон
один раз и дальше обновляться одной командой:

```
git clone -b devin/1786964976-backend-integration https://github.com/ivanovoman/StudServis_New StudServis_New2
```

Затем скопировать `.env` из старой папки в новую и работать в новой.

### После обновления

Смотрите, что изменилось:

- менялся **только `api/server.js`** → перезапустить окно с `npm start`
  (Ctrl+C, потом снова `npm start`). Python трогать не нужно.
- менялось что-то в **`backend/`** → перезапустить окно с uvicorn.
- менялся **`package.json`** → выполнить `npm install`.
- менялся **`backend/requirements.txt`** → выполнить
  `pip install -r backend/requirements.txt`.

Посмотреть, что пришло с обновлением:

```
git log --oneline -5
```

## Что уже работает

- **⚙ Настройки работы** — тема, вуз, **число глав**, методичка файлом
  (PDF/DOCX/TXT), пожелания, загрузка своих источников. Методичка
  разбирается сразу: видно, какие требования распознаны и по какой цитате.
  Все настройки доходят до модели и влияют на текст.
- **1. Анализ проблемы** — разбор темы с опорой на реальные публикации.
- **2. План работы**
- **3. Введение**
- **4. Собрать курсовую** — по готовому плану пишет введение, каждый
  раздел и заключение, показывая ход работы. Долго: 15-25 минут.
  По ходу сверяет ссылки на статьи кодексов и помечает неверные.
  В конце — скачивание .docx по ГОСТ.
- **5. Подобрать источники** — публикации открытого доступа по теме из
  OpenAlex и КиберЛенинки, со ссылками на первоисточник.
- **6. Оформить по ГОСТ** — сборка .docx: поля, шрифт, интервалы,
  нумерация страниц.
- **7. Проверить на ИИ** — свой детектор: процент машинности и список
  конкретных претензий с советами, что переписать.
- **8. Написать речь** — вставить текст работы, получить речь для
  защиты и вероятные вопросы комиссии.

Пункты 5-7 не обращаются к языковой модели: они работают с готовым
текстом, поэтому ключ для них не нужен и суточную квоту они не тратят.
А вот Python-бэкенд нужен обязательно.

## Если что-то не так

**«Python-бэкенд недоступен»** при загрузке файла
→ не запущено окно 1, или оно упало. Посмотрите, что там написано.

**`npm start` ругается на модуль**
→ не выполнен `npm install`.

**`python: command not found`**
→ на Windows попробуйте `py -m uvicorn app.main:app --port 8000`.

**`No module named uvicorn`**
→ не выполнен `pip install -r backend/requirements.txt`, либо pip
поставил пакеты в другой Python. Помогает `python -m pip install -r
backend/requirements.txt` — так пакеты точно уйдут в тот же Python.

**Порт занят**
→ `set PORT=3001 && npm start` (Windows) или `PORT=3001 npm start`
(Linux/macOS). Для Python: `--port 8001`, но тогда Node не найдёт его —
пропишите `PY_BACKEND_URL=http://127.0.0.1:8001` в `.env`.

**Ошибка «ключ отклонён (401)» при генерации**
→ ключ недействителен: удалён, отозван или удалён сам аккаунт.
Перевыпустите его. Покупка кредитов в этом случае не помогает.

**Ошибка «429» или «упёрлись в лимит»**
→ исчерпана бесплатная квота (у OpenRouter это 50 запросов в сутки).
Подождите до сброса или подключите второго поставщика:
`LLM_FALLBACK_PROVIDER=gigachat` в `.env`. См. `docs/LLM_PROVIDERS.md`.

**Не видно, какой поставщик подхватился**
→ откройте http://localhost:3000/api/health — там список того, что
сервер видит, и в каком порядке будет пробовать.

**GigaChat: `unable to verify the first certificate`**
→ не установлен сертификат Минцифры. Быстрое решение — добавить в
`.env` строку `GIGACHAT_INSECURE_TLS=1`.

**Крякозябры в консоли Windows**
→ выполните `chcp 65001` перед запуском. На работу сайта не влияет.

## Тесты

```
cd backend
python -m pytest
```

Ожидается: `377 passed, 1 skipped, 1 xfailed` примерно за 3 секунды.
Пропущенный тест требует ключа OpenRouter и живой сети, `xfailed` —
известная незакрытая мелочь. Оба состояния нормальны, чинить нечего.

Если Python ругается `No module named 'app'` — вы запустили pytest не из
папки `backend`. Вернитесь в неё, либо запустите так:

```
cd backend
PYTHONPATH=. python -m pytest        (Linux / macOS)
set PYTHONPATH=. && python -m pytest (Windows)
```
