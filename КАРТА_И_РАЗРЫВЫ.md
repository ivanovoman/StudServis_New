## Главное в трёх пунктах

1. **Бэкенд — Python/FastAPI, а не Node.** В присланном разборе ядро
   названо «Backend Node.js». Это не так: Node (`api/server.js`, 1500
   строк) раздаёт статику, держит генерацию `/api/generate` и сборку
   `/api/assemble`, а вся содержательная работа — источники, ГОСТ,
   детектор, методичка, оплата, учётные записи — живёт в Python
   (9795 строк в `backend/app/modules/`). Планировать надо от Python.

2. **Три готовых модуля выпали из продукта.** Вход, оплата и список
   сохранённых работ подключены только к ретро-интерфейсу. Ретро я по
   вашему решению убрал из доступа — значит этих функций у пользователя
   сейчас нет вообще, хотя код написан и покрыт тестами.

3. **Пораздельного написания нет, но промпты для него готовы.** В
   `api/prompts.js` лежат `section_plan`, `section_write`,
   `section_polish`, `conclusion` — их использует сборка внутри себя.
   Наружу торчит только кнопка «собрать всё целиком».

## Разрывы по важности

### Очередь 1. Вернуть потерянное (код готов, нужна связка)

1. **Вход и регистрация в современном интерфейсе.** Без него не
   работают ни оплата, ни личный список работ. Сейчас сервер пускает
   всех как анонимов (`spendWork` → `allowed: true, reason:
   'anonymous'`).
2. **Список сохранённых работ.** Сборка уже пишет работу по частям на
   сервер, но ключ владельца в современном виде пустой: в
   `modern-sheets.js` стоит `window.StudWorks ? … : ''`, а `works.js`
   не подключён. То есть трёхминутная сборка никуда не сохраняется.
3. **Оплата.** Модуль ЮKassa готов, тарифы заданы (290 ₽ разово,
   590 ₽ месяц). Без реквизитов от вас включать нечего, но кнопку и
   экран сделать можно заранее.
4. **Загрузка методички файлом.** Эндпоинт `/api/v1/projects/upload/
   methodichka` работает, разбор возвращает поля (шрифт, поля, объём).
   В современных настройках — только текстовое поле.

### Очередь 2. Главное по сути — управляемое написание

5. **Работа по разделам вместо «собрать всё».** Промпты готовы.
   Сценарий: выбрать пункт плана → увидеть предложенную структуру
   раздела → подтвердить или поправить → получить текст → принять.
   Это прямо то, о чём написано в замечаниях, и это действительно
   важнее остального: трёхминутная сборка вслепую даёт результат,
   который студент не контролирует.
6. **План как список, а не текст.** Чтобы работать по разделам, план
   должен стать структурой: пункты можно переставить, переименовать,
   удалить. Сейчас это простыня текста.
7. **Редактор результата.** Хотя бы правка текста раздела перед
   выгрузкой, с пересчётом знаков.

### Очередь 3. Обвязка

8. **Очереди (`tasks` пуст).** Пока пользователей мало, сборка идёт
   прямо в запросе. При нескольких одновременных это ляжет.
9. **Слайды к защите.** Речь есть, слайдов нет.
10. **RAG на Qdrant.** `rag_service` умеет нарезать текст, векторной
    базы нет. Нужен для «стиля Коколова» и опоры на загруженные
    источники.

## Что предлагаю делать

Начать с очереди 1: она возвращает в продукт три готовых модуля и
занимает меньше всего времени. Прямо сейчас сервис умеет писать текст,
но не умеет ни узнать пользователя, ни сохранить ему работу, ни взять
деньги — при том, что весь код для этого написан.

Затем очередь 2 — она меняет сам продукт: из «нажми кнопку и жди три
минуты» в «собери работу по частям, контролируя каждую».
