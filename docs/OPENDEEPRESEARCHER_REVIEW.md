# Разбор OpenDeepResearcher и что брать в модуль 1

Репозиторий: https://github.com/mshumer/OpenDeepResearcher
(2.8k звёзд, 8 коммитов, последний — май 2025; фактически это один
Colab-ноутбук на ~345 строк, не библиотека).

## Что там сделано

Итеративный исследовательский цикл:

```
запрос пользователя
   ↓
LLM генерирует до 4 поисковых запросов
   ↓
┌─→ SERPAPI ищет по всем запросам параллельно
│      ↓
│  дедупликация ссылок внутри итерации
│      ↓
│  по каждой ссылке ПАРАЛЛЕЛЬНО:
│     Jina тянет текст → LLM судит «полезна ли страница» (Yes/No)
│                      → LLM извлекает релевантный кусок
│      ↓
│  LLM смотрит на накопленный контекст и решает:
└──── нужны ли новые запросы, или <done>
   ↓
LLM пишет итоговый отчёт по всему собранному контексту
```

Четыре роли LLM: генератор запросов, судья релевантности, экстрактор
контекста, автор отчёта.

## Что в этом подходе действительно ценно

**1. Разделение «судья» и «экстрактор».** Сначала дешёвый вопрос
«полезна ли страница» с ответом одним словом, и только для прошедших —
дорогое извлечение. Экономия на порядок, а у нас free-модели с
лимитами, так что это прямо в нашу пользу.

**2. Критерий остановки задаёт сама модель.** Цикл идёт не фиксированное
число раз, а пока LLM не скажет `<done>`, глядя на накопленный контекст.
Плюс жёсткий лимит итераций как страховка. Это честный ответ на вопрос
«сколько искать» — тот же принцип, что ваше «зависит от темы».

**3. Дедупликация внутри итерации** с сохранением связи ссылка →
породивший её запрос. Мелочь, но без неё одна и та же страница
обрабатывается несколько раз.

**4. Всё параллельно** через `asyncio.gather`. У нас роутер уже
асинхронный, ложится один в один.

## Чего там нет и почему брать «как есть» нельзя

**Платные ключи в основе.** SERPAPI (~$50/мес) и Jina — оба платные.
Это противоречит требованию «только free».

**Никакой проверки достоверности.** LLM решает «полезна ли страница»,
но никто не проверяет, существует ли источник и правда ли в нём то, что
модель «извлекла». Для блога сойдёт, для курсовой по праву — нет: мы
уже видели, как модель выдумывает `№ 555-ФЗ` и дела с несуществующими
фирмами.

**Источники не цитируются.** В финальный отчёт идёт склеенный текст
контекстов, ссылки на конкретные страницы теряются. Для работы нужен
список литературы с привязкой утверждение → источник.

**Нет отбора по качеству.** Годится любая страница из выдачи Google.
Для научной работы нужны рецензируемые публикации, а не блоги.

**Один общий контекст.** Всё сваливается в один список и подаётся в
финальный промпт. На длинной работе это упрётся в окно контекста;
нам нужен RAG с привязкой к разделам.

## Проверка: есть ли бесплатная замена SERPAPI

Проверил доступность источников без ключей:

| Источник | Статус | Годится |
|---|---|---|
| **OpenAlex API** | HTTP 200, без ключа | **да** |
| **CrossRef API** | HTTP 200, без ключа | **да** |
| CyberLeninka | HTTP 200, только HTML | парсить |
| CORE | таймаут | нет |
| DuckDuckGo HTML | HTTP 202 (антибот) | ненадёжно |

Главная проверка — русская юридическая тематика. OpenAlex по запросу
«субсидиарная ответственность контролирующих лиц банкротство»:

```
найдено 73 работы
[2023] СУБСИДИАРНАЯ ОТВЕТСТВЕННОСТЬ КОНТРОЛИРУЮЩИХ ЛИЦ...  OA=True  doi:10.25683/volbi.2023.64.711
[2025] Ответственность членов совета директоров...          OA=True  law-journal.hse.ru
[2021] Триада правовых понятий «банкротство»...             OA=True  doi:10.18411/lj-04-2021-266
```

По всем пяти темам, на которых я тестировал модуль 1:

| Тема | OA-работ | Из них русских (из 25) | Время |
|---|---|---|---|
| Субсидиарная ответственность | 111 | 23 | 2.5 с |
| Оспаривание сделок | 82 | 22 | 1.1 с |
| Компенсация за товарный знак | 74 | 22 | 1.1 с |
| Налоговое планирование | 224 | 14 | 0.9 с |
| Бизнес-модель стартапа | 1334 | 24 | 1.2 с |

Материала достаточно, работает за секунду, фильтр `is_oa:true` даёт
ровно то, что вы требовали — только Open Access. И у каждой записи есть
**DOI**, то есть проверяемый идентификатор вместо выдуманного номера.

## Что предлагаю взять в модуль 1

Сейчас этап выдаёт `search_directions` — описания того, что искать
(«практика окружных судов за последние три года»). Это правильно, но
это ещё не источники.

Предлагаю достроить этап до **проверяемой источниковой базы**:

```
анализ темы (готов)
   ↓ search_directions
LLM превращает направления в поисковые запросы     ← идея ODR
   ↓
OpenAlex + CrossRef, параллельно, фильтр is_oa     ← вместо SERPAPI
   ↓
дедупликация по DOI                                 ← идея ODR
   ↓
LLM-судья: релевантна ли работа теме (по заголовку  ← идея ODR,
и абстракту, дёшево, ответ одним словом)              но без Jina
   ↓
отбор: год, наличие OA-полнотекста, тип публикации  ← наше
   ↓
проверка: DOI резолвится, ссылка живая              ← наше, главное
   ↓
источники с DOI → в RAG и в список литературы
```

Ключевые отличия от оригинала:

- **вместо SERPAPI** — OpenAlex и CrossRef: бесплатно, научные
  публикации, есть DOI и флаг Open Access;
- **вместо Jina** — абстракты из того же API, а полный текст тянем
  только для OA-работ (у нас уже есть извлечение PDF в `rag_service`);
- **добавляем верификацию** — каждый DOI резолвится, каждая ссылка
  проверяется живой; несуществующий источник в работу не попадает;
- **сохраняем связь** утверждение → источник, чтобы собрать список
  литературы по ГОСТ, а не потерять ссылки в общем контексте;
- **критерий остановки от LLM** берём как есть — с жёстким лимитом
  итераций, чтобы бесплатные модели не крутились вечно.

## Оценка подхода в одну фразу

Архитектура цикла хорошая и её стоит скопировать; инфраструктура
(SERPAPI + Jina + отсутствие верификации) нам не подходит и заменяется
на бесплатную и более строгую. Главное, чего в оригинале нет и что для
курсовой критично, — **проверка, что источник существует**.

## Риски, которые надо иметь в виду

- OpenAlex без ключа имеет мягкий rate limit; вежливый режим
  (`mailto` в User-Agent) даёт больше квоты, нужно указать почту.
- Покрытие русской юриспруденции в OpenAlex неполное: 73–111 работ по
  теме — достаточно для курсовой, но не исчерпывающе. CyberLeninka
  стоит добавить парсером как второй источник.
- Судья на free-модели будет ошибаться. Ошибка в сторону «не полезна»
  дешёвая (потеряли источник), в сторону «полезна» — дорогая (мусор
  в работе). Промпт надо смещать к строгости.
