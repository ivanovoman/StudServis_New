# Разбор ИИ-детектора v7

> **Обновлено после калибровки на статьях автора.** Первоначальный
> вывод «разделяющая способность 0.05» оказался неверен — он был
> артефактом сравнения. См. раздел «Калибровка» в конце: после
> устранения артефакта AUC = 0.893, детектор работает.

Проверял не по описанию, а запуском: вытащил движок из HTML в
`node`-модуль и прогнал на реальных текстах — ваших диссертациях,
синтетических ИИ-текстах и живой прозе.

## Что это такое

55 метрик в 17 кластерах, разделённых на две группы: «улики ИИ»
(K1–K8, KG) и «улики человека» (H1–H5, K9, HA, HE). Итог считается так:

```
sAI   = взвешенное среднее ИИ-кластеров
sHU   = взвешенное среднее человеческих кластеров
delta = sAI − 1.6 × sHU
pAI   = sigmoid(delta × 8)
```

Плюс жанровый коэффициент: матрица `GK` глушит метрику там, где она
для жанра нормальна. Например, «клише» в академическом тексте берётся
с коэффициентом 0.12, а в неформальном — 1.0.

**Это сделано грамотно.** Идея «улики за» минус «улики против» с
жанровой поправкой — правильная архитектура, и она прямо отвечает на
ваш тезис про живость: детектор уже умеет не штрафовать академический
текст за то, что для него норма.

## Три проблемы, найденные измерением

### 1. Разделяющая способность почти нулевая

| Выборка | Средний pAI |
|---|---|
| Синтетические ИИ-тексты (3 шт.) | **0.746** |
| Живая человеческая проза (3 шт.) | **0.696** |

Разница — **0.05**. Направление верное, но порог, который отделил бы
одно от другого, провести невозможно: распределения перекрываются
почти полностью.

### 2. Ваши собственные тексты он не считает человеческими

Прогон по 26 разделам двух ваших диссертаций:

```
min 0.082 | p25 0.253 | медиана 0.341 | p75 0.408 | max 0.618
```

Один раздел получил **0.618** — то есть детектор счёл вашу живую
диссертацию машинной. При этом синтетический ИИ-текст получал 0.67–0.79.
Пересечение диапазонов означает ложные срабатывания на настоящих работах.

### 3. Оценка зависит от длины сильнее, чем от содержания

Один и тот же ваш раздел, обрезанный до разной длины:

| Длина | pAI |
|---|---|
| 300 симв | 0.677 |
| 600 симв | 0.506 |
| 1200 симв | 0.387 |
| 2500 симв | 0.398 |
| 5000 симв | 0.235 |
| 9000 симв | 0.253 |

Текст один и тот же, а оценка меняется в **2.7 раза**. Это делает
абсолютное значение pAI непригодным как порог приёмки: раздел на 5000
знаков и абзац на 300 знаков живут в разных шкалах. Причина — многие
метрики нормируются на число предложений и на коротких фрагментах
насыщаются.

## Можно ли использовать его для гуманизации: нет, и вот почему

Я проверил прямо: взял ИИ-текст (pAI = 0.776) и накидывал дешёвые
приёмы, ничего не меняя по существу.

| Приём | pAI | Итог |
|---|---|---|
| исходный ИИ-текст | 0.776 | — |
| + «я считаю», «на мой взгляд» | 0.819 | ✗ стало хуже |
| + сленг «короче, реально» | 0.862 | ✗ стало хуже |
| + сомнения «не уверен, возможно» | 0.639 | ↓ 0.14 |
| + эмоции «возмущает, удивительно» | 0.674 | ↓ 0.10 |
| + сноски `[1] См.: Иванов. С. 42.` | 0.640 | ↓ 0.14 |
| **+ всё сразу** | **0.500** | ↓ 0.28 |

Приписка двух фальшивых сносок и фразы «возможно, я ошибаюсь» роняет
оценку на 0.28 — при том что **текст остался ровно тем же ИИ-текстом**.

Отсюда главный вывод: если поставить этот детектор целевой функцией
humanizer'а, оптимизатор найдёт именно эти дыры. Мы получим работы,
нашпигованные «я считаю», «короче» и выдуманными сносками, — детектор
будет доволен, научный руководитель нет. **Метрика, ставшая целью,
перестаёт быть метрикой.**

Отдельно: приёмы, которые детектор поощряет (сленг, я-нарратив, эмоции),
для курсовой работы прямо вредны. Оптимизация по нему толкает текст в
сторону, противоположную нужной.

## Где он полезен

Не как ворота, а как **диагностика по кластерам**. Ценность не в pAI,
а в разбивке: `K1 Лексика`, `K4 Ритм`, `K5 Структура`, `K7 Синтаксис`.
Эти подсчёты честные и говорят, *что именно* не так с текстом —
«симметричные списки», «трёхчастность», «ровный ритм». Это готовые
задания для переписывания, и их нельзя обмануть припиской сносок,
потому что мы читаем не итог, а конкретный кластер.

Поэтому предлагаю встроить его так:

- забираем **кластерные оценки K1–K8**, а не итоговый pAI;
- используем их как подсказки humanizer'у, что править;
- решение «годится / не годится» принимаем по нашим порогам,
  откалиброванным по вашим текстам (`acceptance.py`);
- pAI показываем пользователю справочно, с оговоркой о длине.

## Нужен ли ИИ для ИИ-детектирования

Коротко: **сейчас — нет.**

Статистический детектор дёшев, работает офлайн, объясним и не сливает
текст работы наружу. Нейросетевой (перплексия через языковую модель,
дообученный классификатор) точнее, но:

- нужна GPU или платный API — против вашего «только free-модели»;
- отправка текста работы во внешний API — риск утечки;
- необъясним: скажет «0.8», но не скажет, что править, — а нам нужно
  именно второе;
- главное: **любой детектор, ставший целевой функцией, ломается**.
  Нейросетевой сломается так же, только дороже.

Что реально повышает точность без ИИ — калибровка на размеченных
данных. У нас уже есть эталон: ваши тексты как «человек» и выдача
free-моделей как «ИИ». Этого хватит, чтобы подобрать веса и увидеть
честную разделяющую способность. Возвращаться к вопросу о нейросетевом
детекторе стоит только если после калибровки разделение останется
плохим.

## Готовые решения с GitHub

Подключить технически можно, но ни одно не закрывает нашу задачу:

| Решение | Проблема для нас |
|---|---|
| `roberta-base-openai-detector` | обучен на GPT-2 и на английском; на русском академическом бесполезен |
| Binoculars, DetectGPT, Fast-DetectGPT | нужны две языковые модели локально — GPU, вес в гигабайтах |
| GPTZero / Originality (API) | платные, внешние, текст уходит наружу |
| RuATD (русский) | обучен на новостях и соцсетях, не на научном стиле |

Общая беда: все обучены на чужих доменах. Русская курсовая по праву —
не то, на чём их калибровали, и переносимость тут низкая. Плюс все они
дают тот же необъяснимый скаляр вместо указания, что править.

Разумный компромисс — взять из открытых решений **идеи метрик**
(перплексия, burstiness — они у вас уже есть), а не сами модели.

## Про живость в научном тексте — принято

Ваша правка учтена, и она согласуется с замерами. Числа по вашим
текстам:

| | Статьи | Дисс. 2026 | Дисс. 2002 |
|---|---|---|---|
| Разброс длин предложений | 7.86 | 20.82 | 16.25 |
| Доля коротких (<8 слов) | 30.6% | 22.7% | 14.0% |

В диссертациях коротких предложений от 14 до 23 процентов — то есть
живость там **уже есть**, просто её меньше, чем в статьях. Это не
статьи против науки, а разная дозировка одного приёма.

Что меняю в порогах: нижнюю границу доли коротких предложений поднимаю
и делаю осмысленной для научного текста, а не просто «не ноль».
Ориентир — нижний край вашего же диапазона, около 12–14%, вместо
нынешних 5%. Верх не ограничиваю: короткая фраза в научном тексте почти
всегда работает на читателя.

## Что нужно от вас

1. **Пара размеченных примеров** «это писал я» и «это выдала модель» —
   10–15 текстов хватит, чтобы откалибровать веса и получить честную
   цифру разделяющей способности.
2. Подтверждение, что забираем **кластеры вместо pAI** как сигнал для
   humanizer'а.

# Калибровка на реальных данных

Автор прислал 4 свои статьи (IT-бизнес-модели, авторские права,
ИС при банкротстве, открытие кофейни). Это дало настоящий класс
«человек». Класс «ИИ» я собрал сам: 8 статей на те же и смежные темы
через free-модели OpenRouter (minimax-m3, minimax-m2.7, nemotron-3-ultra).

## Артефакт, который переворачивал результат

Первое измерение дало **AUC 0.375** — детектор работал хуже монетки, и
в обратную сторону: тексты моделей он считал более человеческими, чем
статьи автора.

Причина оказалась не в детекторе. Я сравнил формальные признаки:

| Признак | ИИ (из API) | Человек (из PDF) |
|---|---|---|
| `**жирный**` | 18.8 | **0.0** |
| `## заголовки` | 7.9 | **0.0** |
| списки `-` | 6.1 | **0.0** |
| переносов строк | 54.8 | 309.3 |

Тексты человека пришли из PDF, где разметка теряется при извлечении.
Тексты моделей — из API, с markdown. Детектор честно считал метрики
кластера K2 «Оформление» и разделял **источник данных, а не авторство**.
Сравнение было нечестным с самого начала, и виноват в этом я.

## Результат после устранения артефакта

Снял markdown с обеих сторон и переизмерил на той же выборке:

| Метрика | До | После |
|---|---|---|
| Средний pAI, человек | 0.447 | 0.447 |
| Средний pAI, ИИ | 0.355 | **0.580** |
| Разделение | −0.091 | **+0.134** |
| **AUC** | **0.375** | **0.893** |

AUC 0.893 — это рабочий детектор. Мой предыдущий вывод «разделяющая
способность 0.05, порог провести нельзя» был неверен: я измерял
синтетику против синтетики и сравнивал markdown с PDF.

## Что это меняет в выводах

**Остаётся в силе:** детектор нельзя использовать как целевую функцию
humanizer'а. Проверка на обманываемость никуда не делась — две
фальшивые сноски и «возможно, я ошибаюсь» роняют оценку на 0.28 без
изменения сути. Оптимизация по нему по-прежнему приведёт к сленгу и
выдуманным источникам.

**Меняется:** как диагностика он ценнее, чем я говорил. При пороге 0.5
на калибровочной выборке: точность 80%, **ни один ИИ-текст не
пропущен**, но 3 из 7 живых статей помечены ложно.

Ложных срабатываний слишком много, чтобы ставить детектор воротами —
он забраковал бы почти половину настоящих работ. Поэтому роль такая:

- сигнал «стоит присмотреться», а не «брак»;
- показываем пользователю с оговоркой;
- решение о приёмке — по нашим порогам из `acceptance.py`.

## Правило для всей системы

Перед любой стилевой оценкой снимаем markdown:
`humanizer/detector_bridge.py::strip_markdown`. Наш генератор выдаёт
размеченный текст, эталон лежит в PDF — сравнивать их напрямую нельзя.
Это касается не только детектора, но и всех сравнений с профилем стиля.

# Кластерная диагностика: honest подсчёты в явном виде

Реализовано: `backend/app/modules/humanizer/diagnostics.py`,
движок вендорен в `humanizer/vendor/detector_engine.js`,
API — `POST /api/v1/humanizer/analyze`.

## Надёжность кластеров пришлось перемерить

Раньше я советовал забирать «K1 Лексика, K4 Ритм, K5 Структура,
K7 Синтаксис». Это была интуиция, и она частично не подтвердилась.
На честных данных (разметка снята с обеих сторон) AUC каждого кластера:

| Кластер | AUC | Сигнал |
|---|---|---|
| K6 Нейтральность | 1.000 | сильный |
| K7 Синтаксис | 0.000 | сильный (обратный) |
| K4 Ритм | 0.848 | сильный |
| H1 Живые маркеры | 0.125 | сильный |
| K8 Дискурс | 0.714 | средний |
| K5 Структура | 0.241 | средний |
| K1 Лексика | 0.277 | средний |
| **K3 Статистика** | **0.536** | **шум** |
| **KG, H4, HA, HE** | **~0.5** | **шум** |

Пять кластеров из семнадцати оказались неотличимы от монетки — они
исключены. K1 и K5, которые я рекомендовал, работают слабее, чем K6 и
K4, о которых я не говорил. Веса теперь взяты из замера.

## Эталон автора обязателен

Абсолютное значение кластера бесполезно. Медиана H1 «живые маркеры» у
автора — **0.021**: их почти нет и в его собственных текстах.
Жаловаться на низкий H1 значит требовать от генерации быть живее
автора, чей стиль копируем.

Поэтому посчитан baseline по **33 текстам автора** (7 фрагментов статей
+ 26 разделов диссертаций): медиана и p90 каждого кластера. Претензия
предъявляется, только когда кластер вышел за **его** диапазон.

## Результат

Число претензий на текст:

| | Значения | Среднее |
|---|---|---|
| Статьи автора | 1, 0, 3, 2, 1, 1, 0 | **1.14** |
| Тексты моделей | 7, 4, 3, 2, 2, 2, 4, 4 | **3.50** |

**AUC по числу претензий = 0.911** — выше, чем у pAI (0.893), и в
отличие от него объяснимо: видно, какая именно претензия сработала.

Какие претензии различают классы лучше всего:

| Претензия | Человек | ИИ |
|---|---|---|
| Нет живых маркеров | 0/7 | **6/8** |
| Ровный ритм | 0/7 | **4/8** |
| Машинное оформление | 1/7 | 4/8 |
| Слишком линейно | 3/7 | 8/8 |
| Стерильная нейтральность | 0/7 | 2/8 |

## Что отдаёт API

```
POST /api/v1/humanizer/analyze  {"text": "..."}
```

```json
{
  "clean": false,
  "p_ai": 0.62,
  "p_ai_note": "справочно: зависит от длины текста и обманывается
                приписками, порогом приёмки не является",
  "findings": [
    {"title": "Ровный ритм", "score": 0.41, "author_median": 0.28,
     "excess": 0.45, "reliability": "сильный",
     "advice": "Перемешать длины предложений…"}
  ],
  "rewrite_tasks": ["Ровный ритм: Перемешать длины предложений…"],
  "ignored_as_noise": ["K3", "KG", "H2", "H4", "H5", "HA", "HE"]
}
```

Пример на живых данных. ИИ-текст — 7 претензий, ваша статья — 1:

```
=== ИИ-ТЕКСТ ===        pAI 0.62, претензий 7
   - Нет живых маркеров: Добавить авторский голос…
   - Слишком линейно: Разрешить отступления и возвраты к мысли…
   - Машинное оформление: Убрать избыточные выделения…
   - Стерильная нейтральность: Добавить авторскую позицию…
   - Обобщённый дискурс: Добавить конкретику: цифры, названия…

=== ВАША СТАТЬЯ ===     pAI 0.40, претензий 1
   - Шаблонная структура: Сломать симметрию…
```

`rewrite_tasks` — это готовый вход для humanizer'а: не «текст на 62%
машинный», а «перемешай длины предложений» и «добавь конкретику».
Такое задание нельзя выполнить припиской фальшивой сноски.
