# StudRabots Retro — что нужно от заказчика для старта

Чек-лист артефактов. Формат важен: чем ближе к указанному, тем меньше времени
уйдёт на адаптацию и тем меньше шансов, что модуль придётся переписывать.

Складывать в `incoming/` (эта папка в .gitignore — секреты и сырые материалы
не попадают в репозиторий).

---

## БЛОК 1. Блокирующее (без этого нельзя начинать)

### 1.1. Ключ OpenRouter
- `OPENROUTER_API_KEY` — прислать отдельно, НЕ в чат с кодом, НЕ в коммит.
- Нужен, чтобы проверять реальную работу цепочки, а не писать в пустоту.
- Если ключа пока нет: https://openrouter.ai/keys, режим free-моделей.

### 1.2. Решение по стеку (см. вопрос в чате)
Текущий код в ветке — **Node.js/Express**, ТЗ описывает **Python/FastAPI**.
Пока это не зафиксировано, любой написанный код — риск выброса.

## БЛОК 2. Ваш готовый код (интегрируем как есть)

### 2.1. Генератор документов по ГОСТ
- Файлы `.py` (или `.js`), целиком, включая вспомогательные модули.
- Что именно нужно знать:
  - точка входа: имя функции и её сигнатура (что на входе — Markdown? dict? список секций?);
  - что на выходе — путь к файлу, байты, поток?
  - какие внешние зависимости (python-docx, pandoc, LibreOffice, шрифты?);
  - поддерживает ли PDF или только DOCX;
  - какой ГОСТ реализован (7.32-2017 / Р 7.0.11-2011 / 7.0.5-2008).
- Плюс **1–2 примера готового .docx**, который этот код выдаёт — как эталон,
  с которым буду сверять результат после интеграции.
- Если есть шаблон `.dotx`/титульник конкретного вуза — тоже.

### 2.2. ИИ-детектор
- Код целиком + сигнатура: `check(text) -> ?` (число 0..1, dict, класс?).
- Порог, при котором текст считается «палевным» (например, score > 0.35).
- Зависимости: чистые эвристики / sklearn-модель / веса модели?
  Если веса — прислать файл весов, они обычно не в репозитории.
- Работает на русском? На каком минимальном объёме текста (абзац / 1000 слов)?
- 2–3 примера: текст + какой score он должен давать. Нужны для регресс-тестов.

## БЛОК 3. Промпты и методология

### 3.1. Промпт по написанию курсовой
- В том виде, в каком он у вас есть (docx/txt/md — неважно).
- Важно пометить: это **один большой промпт** или **набор по этапам**?

### 3.2. Поэтапные инструкции (то, что вы предложили составить)
Максимально полезный формат — по одному блоку на этап:

```
ЭТАП: introduction
ВХОД: тема, анализ, план
ЗАДАЧА: <текст промпта>
ОБЪЁМ: 1200-1500 слов
ОБЯЗАТЕЛЬНО: актуальность, объект, предмет, цель, задачи, методы
ЗАПРЕЩЕНО: <клише>
КРИТЕРИЙ ГОТОВНОСТИ: <как понять, что этап пройден успешно>
ПРИМЕР ХОРОШЕГО РЕЗУЛЬТАТА: <фрагмент>
```

Этапы, которые уже заложены в коде (`api/prompts.js`) — можно править их:
`analysis`, `plan`, `introduction`, `section_plan`, `section_write`,
`section_polish`, `table_generate`, `table_check`, `conclusion`, `polish`.

**«Критерий готовности» и «пример хорошего результата» — самое ценное.**
Без них невозможно автоматически проверять качество, останется «на глаз».

### 3.3. Видение поэтапного создания работы целиком
- Порядок этапов, что после чего, где нужна пауза на подтверждение пользователем,
  где развилки (например: «если тема практическая → добавить главу с анализом дел»).
- Где проходит граница «бесплатно / платно».

## БЛОК 4. Материалы для RAG (стиль Коколова)

Это то, от чего напрямую зависит, будет ли текст похож на человека.

### 4.1. Тексты Коколова
- **Минимум: 5–10 работ / статей целиком** в .docx, .txt или .md.
- Больше — лучше. 2 текста не хватит: не из чего извлекать закономерности.
- Желательно с пометкой типа: статья / курсовая / раздел / введение / заключение.

### 4.2. Правила стиля (если сформулированы явно)
- Список запрещённых слов и оборотов.
- Список любимых конструкций и связок.
- Типичная длина предложения/абзаца, любые «так пишу — так не пишу».
- Если явных правил нет — извлеку их из текстов п.4.1 автоматически и дам
  на утверждение.

### 4.3. Эталонные примеры
- 2–3 введения, 2–3 заключения, 1–2 списка литературы, которые вы считаете
  образцовыми. Пойдут в коллекцию `examples_good`.

## БЛОК 5. Источники и предметная область

### 5.1. Профиль предметной области
- Только юриспруденция или шире? От этого зависят парсеры и промпты.
- Типовые темы (5–10 примеров реальных заказов) — для тестового прогона.

### 5.2. Источники
- Подтвердить список: CyberLeninka, eLibrary (open), Google Scholar,
  сайты судов (какие именно — КАД, sudact, ВС РФ?).
- Есть ли «белый список» изданий/авторов, которым доверяем.
- Формат библиографии: ГОСТ 7.0.5-2008 или методичка вуза (прислать методичку).

## БЛОК 6. Платежи и юр. часть (нужно к этапу 3, не сейчас)

- ЮKassa: shopId + секретный ключ (тестовый магазин на старте).
- Прайс: что платно, сколько стоит, есть ли пакеты/подписка.
- Кто юрлицо/самозанятый для чеков (54-ФЗ).
- Текст дисклеймера и пользовательского соглашения (или мой черновик на правку).
- Политика хранения: сколько дней храним работы, автоудаление.

## Приоритет присылки

| Очередь | Что | Зачем именно сейчас |
|---|---|---|
| 1 | Ключ OpenRouter | без него ничего не проверяется |
| 2 | Код ГОСТ + пример .docx | самый большой готовый кусок, определяет формат данных всего пайплайна |
| 3 | Тексты Коколова (5–10 шт.) | долгая часть: разбор стиля → правила → RAG |
| 4 | ИИ-детектор | нужен к этапу humanizer |
| 5 | Поэтапные промпты | можно догружать по мере готовности этапов |
| 6 | ЮKassa, юр. тексты | этап 3, время есть |

Пункты 1 и 2 достаточны, чтобы начать и закрыть первый рабочий этап.
