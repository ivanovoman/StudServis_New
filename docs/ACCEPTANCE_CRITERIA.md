полностью — это строже, чем пишет сам автор. Если требовать ноль,

## 1. `analysis` — анализ темы

**Машина проверяет:**
- есть 3–5 тезисов ядра темы
- есть логическая дуга (порядок раскрытия)
- есть 5–7 направлений поиска источников
- есть блок рисков шаблонности
- каждое непроверенное утверждение помечено `[нужно проверить: ...]`
- НЕ содержит готового текста работы (нет абзацев прозы > 500 знаков)

**Брак:** выдал готовое введение вместо заметок; ни одной пометки
`[нужно проверить]` при наличии конкретных дел/сумм.

`?? ВОПРОС К ВАМ:` сколько тезисов оптимально — 3, 5 или зависит от темы?

## 2. `plan` — план работы

**Машина:**
- 2–3 главы (или 3, как в обеих ваших работах)
- 2–4 параграфа на главу, нумерация 1.1, 1.2, 2.1
- у каждого параграфа: название + описание 2–3 предложения + норма/практика +
  переход к следующему
- есть «Выводы по главе N» после каждой главы ← **есть в обеих ваших работах**
- нумерация сквозная, без пропусков

**Брак:** параграф без указания источниковой базы; дробление на 6+ параграфов
в главе (мельчит).

`?? ВОПРОС К ВАМ:` фиксируем 3 главы как стандарт или оставляем 2–3?
В обеих ваших диссертациях — ровно 3 + выводы по каждой.

## 3. `introduction` — введение

**Машина:**
- объём **3500–5000 знаков с пробелами** (не «без пробелов» — см. ниже)
- присутствуют все 6 элементов: проблема, актуальность, изученность,
  цель+задачи, объект+предмет, структура
- не начинается словом «Введение»
- ≥ 2 ссылки на нормы/источники
- задачи соответствуют главам плана (сверка по числу)

⚠️ **Противоречие в текущем промпте:** `plan` требует «7000-10000 знаков
без пробелов» на параграф, `section_write` — «3-4 страницы… 7000-10000
знаков без пробелов». Но 3-4 страницы по ГОСТ (14pt, 1.5) — это
~5000-7000 знаков **с** пробелами. 10 000 без пробелов ≈ 12 000 с
пробелами ≈ 6-7 страниц. Модель пойдёт за большим числом → «вода».

`?? ВОПРОС К ВАМ:` какой объём раздела правильный — 3-4 страницы
(~6000 знаков с пробелами) или 10 000 знаков (~7 страниц)? Нужно одно число.

## 4. `section_plan` — поабзацный план раздела

**Машина:** 6–12 абзацев; у каждого тезис + опора (норма/дело/автор);
нет повторов тезисов из уже написанных разделов.

**Брак:** абзац без указания, на чём основан.

## 5. `section_write` — написание раздела

**Машина:**
- объём по решению вопроса выше
- базовые пороги ритма (см. таблицу)
- ≥ 1 ссылка на норму и ≥ 1 на практику на раздел
  (у вас в праве: 4.67 и 4.61 на 1000 слов)
- не начинается с номера/названия раздела
- нет дословных повторов ≥ 15 слов из предыдущих разделов
- все номера дел/статей либо в базе `sources` с `is_verified=true`,
  либо помечены `[проверить]`

**Брак:** абстрактный текст без единой ссылки; повтор содержания
предыдущего раздела.

`?? ВОПРОС К ВАМ:` минимум кейсов на раздел — 1 или 2? Промпт сейчас
просит «1-2 на главу», но на раздел это разное количество.

## 6. `section_polish` — полировка раздела

**Машина:** после полировки метрики ритма НЕ ухудшились; клише не выросли;

**Машина:** валидный markdown; 2–5 столбцов; 3–10 строк; есть номер и
название; в тексте раздела есть отсылка «в таблице N»; данные не
противоречат тексту.

`?? ВОПРОС К ВАМ:` таблица обязательна в каждом разделе или только там,

## 8. `table_check` — проверка таблицы

**Машина:** число столбцов совпадает во всех строках; нет пустых ячеек;
подпись соответствует содержанию; **перенос в последней ячейке не
потерян** (см. дефект в `docs/GOST_PORT.md`).

## 9. `conclusion` — заключение

**Машина:**
- объём 3000–5000 знаков с пробелами
- отвечает на ВСЕ задачи из введения (сверка по числу задач)
- нет новых фактов, которых не было в тексте работы
- нет ссылок на источники, не встречавшихся ранее
- не начинается словом «Заключение»

**Брак:** заключение вводит новый тезис; не покрывает часть задач.

`?? ВОПРОС К ВАМ:` нужны ли в заключении конкретные предложения по
совершенствованию законодательства? В работе 2026 такая глава есть (3.2).
