## Что конкретно ценно и переживёт переписывание

1. **`api/prompts.js` (260 строк).** Промпты проработаны серьёзно: жёсткие запреты
   на клише, требование конкретики (номера дел, суммы, даты), инструкции по ритму
   абзацев. Это переносится в Python практически копипастом — язык не важен, это текст.
2. **`api/docxExport.js` (462 строки).** Логика ГОСТ-вёрстки. При переходе на Python
   переписывается на `python-docx`, но **алгоритм и правила** (как ломать страницы,
   как нумеровать таблицы, как собирать содержание) уже продуманы и проверены.
3. **Логика fallback между моделями.** ~40 строк, переносится за час.
4. **16 ретро-тем фронтенда.** Чистый HTML/CSS, при переходе на Vue 3 становятся
   наборами CSS-переменных.

## Что придётся выбросить или переделать

- `api/server.js` — при переходе на FastAPI переписывается целиком.
- `public/app.js` (245 строк) — при переходе на Vue 3 переписывается целиком.
  Сейчас это императивный DOM-код, который навешивается на пункты меню по номеру.
- Архитектура «всё в одном файле» — не соответствует модульным границам ТЗ.

## Главное архитектурное расхождение

Код в ветке — **Node.js/Express**. ТЗ описывает **Python 3.11 / FastAPI /
Celery / ChromaDB / SQLAlchemy**.

Это не мелочь. Экосистема ТЗ — питоновская:
- `python-docx` (ваш код ГОСТ, скорее всего, на нём);
- ваш ИИ-детектор (почти наверняка Python — sklearn/эвристики);
- ChromaDB (Python-нативная);
- Celery (Python).

Три из четырёх ключевых компонентов — Python. Держать бэкенд на Node значит
либо переписывать ваш готовый код, либо поднимать второй сервис-сайдкар на
Python и городить между ними HTTP. Оба варианта хуже, чем сразу FastAPI.

**Рекомендация: перенести на Python/FastAPI, забрав из Node-ветки промпты,
правила ГОСТ-вёрстки и логику fallback.** Node-ветку сохранить как рабочее
демо (она сейчас единственное, что вообще запускается).

## Ложные срабатывания сверки ссылок на кодексы (24.09.2026)

`legal_refs.py` сверяет «ст. N КОДЕКС РФ» с оглавлением consultant.ru и
ставит `mismatch`, когда слова рядом со ссылкой не совпадают с
заголовком статьи. На живом прогоне это дало 4 ложных срабатывания из 9:

| Ссылка | Текст работы | Заголовок статьи | Правда? |
| --- | --- | --- | --- |
| ст. 3 ГК | «провозглашает приоритет кодекса» | «Гражданское законодательство и иные акты…» | да, п. 2 ст. 3 |
| ст. 5 ТК | «выстраивает иерархию источников» | «Трудовое законодательство и иные акты…» | да |
| ст. 26 ГК | «ограничивает сделки без согласия родителей» | «Дееспособность несовершеннолетних 14-18 лет» | да |
| ст. 13 ГК | «фильтр» | «Признание недействительным акта госоргана» | да |

Во всех четырёх случаях автор пересказал содержание статьи своими
словами — именно так и пишут научные работы. Алгоритм же ждёт дословного
совпадения с заголовком.

Что делать: понизить `mismatch` до предупреждения «проверьте», когда
номер статьи существует и рядом нет явного противоречия, а красный
статус оставить для случаев, когда статьи нет вовсе (`missing`) или
когда в тексте назван другой кодекс. Иначе пользователь привыкает
игнорировать красное, и настоящая ошибка (вроде «ст. 61.12 ГК» вместо
127-ФЗ) потеряется в шуме.
