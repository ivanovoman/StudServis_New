## Проверка эквивалентности

Порт не «переписан по мотивам» — он сверен с оригиналом прогоном обеих
реализаций на одинаковых данных:

```
JS (оригинал)                          | PY (порт)
------------------------------------------------------------------
  СОДЕРЖАНИЕ                           | СОДЕРЖАНИЕ
  ВВЕДЕНИЕ                             | ВВЕДЕНИЕ
  ГЛАВА 1. Теория                      | ГЛАВА 1. Теория
  1.1. Понятие                         | 1.1. Понятие
  ...
  Таблица № 2.1. Крит                  | Таблица № 2.1. Крит
  ЗАКЛЮЧЕНИЕ                           | ЗАКЛЮЧЕНИЕ

абзацев: JS 18 | PY 18 -> СОВПАДАЕТ
таблица совпадает: True
```

Правила оформления перенесены дословно, потому что в шапке оригинала
указано: «Все параметры визуально проверены через рендеринг в PDF». Ничего
не «улучшено по вкусу».

| Параметр | Значение |
|---|---|
| Шрифт | Times New Roman |
| Основной текст | 14pt, интервал 1.5, по ширине, красная строка 1.25 см |
| H1 | 16pt, КАПС, **не жирный**, по центру, разрыв страницы перед |
| H2 | 14pt, обычный, без разрыва |
| Таблицы | 11pt, шапка по центру, тело влево, границы 1.5pt |

| before/after | везде 0 — отступы делаются пустыми абзацами |

## Одно отличие от оригинала (осознанное)

В python-docx кириллица требует явной установки `w:cs` и `w:eastAsia` в
`rFonts`. Без этого Word подставляет свой шрифт вместо Times New Roman для
русского текста. В JS-библиотеке `docx` это делалось автоматически.
Реализовано в `_style_run()`.

## Найденный дефект (унаследован из оригинала)

`parse_markdown_table` теряет текст, если модель перенесла строку **в самой
последней ячейке** таблицы:

```
|Критерий|Описание|
|---|---|
|Субъект|Контролирующее лицо,
которое давало указания|     <- "которое давало указания" ТЕРЯЕТСЯ
```

Причина: зона таблицы обрезается по последней строке, начинающейся с `|`,
поэтому финальный перенос в неё не попадает. **Внутри** таблицы переносы
склеиваются верно — проблема только в последней строке.

Проверено сравнением: **JS даёт ровно тот же результат**, это не регрессия
порта. Зафиксировано тестом `test_trailing_wrapped_cell_is_lost`
(помечен `xfail(strict=True)` — когда починим, тест сам просигналит).

Это тихая порча данных, а не косметика: часть таблицы молча исчезает из
готовой работы. Чинить надо, но менять поведение вашего проверенного кода
без вашего согласия я не стал.

**Вопрос к вам:** чинить сейчас или оставить как есть до общей ревизии?
Правка на 3 строки — расширить зону таблицы до конца блока, а не до
последней строки с `|`.
