# Поставщики научной литературы: что проверено и что подключено

Дата проверки — 25 сентября 2026 года. Все кандидаты опрошены живыми
запросами из рабочего окружения, русскими и английскими. Проверялись три
вещи: пускает ли база вообще, знает ли она **русские юридические** темы
и отдаёт ли осмысленный абстракт (по коротким аннотациям в две строки
модель писать не может).

## Итог: подключено четыре базы

| База | Ключ | Что даёт | Доля в выдаче по юр. теме |
| --- | --- | --- | --- |
| **КиберЛенинка** | не нужен | русская периодика, **полные тексты** | 4–7 из 8 |
| **Crossref** | не нужен | точная библиография, DOI, русские абстракты | 2 из 8 |
| **OpenAlex** | бесплатный | мировая наука, цитируемость | 1–2 из 8 |
| **DOAJ** | не нужен | гарантированный открытый доступ, длинные абстракты | 0–1 из 8 |

Проверка на трёх темах («коллизии в праве», «субсидиарная
ответственность КДЛ», «цифровые права и смарт-контракты») даёт 8 из 8
релевантных записей за 2–4 секунды, из них половина с DOI.

### Почему именно эти

**КиберЛенинка** остаётся основой: только она отдаёт полный текст
статьи, а не аннотацию. Для русской гуманитарной темы это половина
качества работы.

**Crossref** — главное приобретение. Он регистрирует DOI и поэтому знает
почти всё, что вышло в журналах с настоящей редакцией, включая
ваковские: «Вестник МГПУ. Серия Юридические науки», «Law. Journal of the
Higher School of Economics». По запросу «коллизии в праве» — 1645 статей
с 2019 года. Абстракты бывают на 2000 знаков, длиннее, чем у
КиберЛенинки. И главное: из его метаданных собирается **список
литературы**, реквизиты которого модель иначе выдумывает.

**OpenAlex** с февраля 2026 требует ключ: анонимам оставили около сотни
запросов в сутки на всех сразу. Ключ бесплатный, получается за минуту,
и с ним база отвечает стабильно.

**DOAJ** даёт мало (по русскому праву — единицы записей), но то, что
даёт, точно откроется без платной стены и с абстрактом на 2–3 тысячи
знаков. Держать его единственным нельзя, в дополнение — полезно.

## Отклонённые кандидаты

| База | Что ответила | Почему не подключена |
| --- | --- | --- |
| **eLibrary.ru** | HTTP 403 на сайт, заглушка «К сожалению…» на `rest/getitem` | закрыта для машинного доступа, API только по договору |
| **РГБ** (search.rsl.ru) | HTTP 403 | то же; поиск только через браузер |
| **ИНИОН РАН** | вход гостем проходит, следующий шаг сбрасывает сессию | WebIrbis с сессиями и cp1251; см. разбор ниже |
| **ВИНИТИ РАН** | страница «Заглушка» | сайт не в рабочем состоянии; доступ к РЖ платный |
| **Semantic Scholar** | HTTP 429 на каждый запрос | без ключа не работает, ключ выдают по заявке с обоснованием |
| **CORE** | HTTP 429 | ключ по заявке; обещает 200+ млн работ, стоит вернуться, когда ключ будет |
| **Соционет** | соединение не устанавливается | судя по всему, проект заброшен |
| **Europe PMC** | HTTP 200, 12 175 «результатов» | медицина и биология; по запросу «legal collision» выдаёт статьи про ДТП и ветеринарную экспертизу |
| **arXiv** | HTTP 200 | физика, математика, программирование; по праву пусто |
| **OpenAIRE** | HTTP 200, но формат не разобран | агрегатор европейских репозиториев, ответ в тяжёлом XML-подобном JSON; дублирует то, что уже есть в OpenAlex и DOAJ |
| **Google Scholar** | — | публичного API нет, парсинг запрещён правилами и ловится капчей |

### Про ИНИОН РАН отдельно

Проверен вручную, по шагам. Сайт института жив, каталоги ведут на
`db.inion.ru` — систему WebIrbis. Вход гостем (`UNAME=GUEST`,
`FUNC=CHECK`) проходит, сервер выдаёт идентификатор сессии. Но
следующий шаг — «Начало поиска» — возвращает форму входа: сессия не
удерживается обычным набором cookie.

Пробиться, вероятно, можно. Не стали по трём причинам: интерфейс
сессионный и в кодировке cp1251, то есть парсер будет разваливаться от
любой правки на их стороне; записи ИНИОН — голая библиография без
аннотаций, а нашему конвейеру нужен текст, по которому модель пишет;
пополнение баз после пожара 2015 года резко сократилось.

### Про OAI-PMH КиберЛенинки отдельно

Протокол работает (`cyberleninka.ru/oai?verb=Identify` → 200, записи с
2014 года), но отдаёт скудный Dublin Core: заглавие, авторы, тип,
издатель, ссылка. **Ни года, ни журнала, ни страниц.** Для
библиографической записи это хуже, чем обычный поиск КиберЛенинки,
который даёт год, журнал и аннотацию. Поэтому OAI-PMH не подключён —
он тут не помощник.

Выходные данные нашлись в другом месте: в мета-тегах страницы самой
статьи (`eprints.pagerange`, `citation_issue`, `citation_issn`). Оттуда
мы их и берём — см. ниже.

### Про Europe PMC и arXiv отдельно

Обе базы живые и бесплатные, но профильные. Подключать их «на всякий
случай» вредно: они принесут статьи не по теме, те займут места в
выдаче и попадут в промпт. Смысл появится, если сервис пойдёт за
пределы юридических и гуманитарных тем — тогда их стоит включать по
области работы, а не всегда.

## Что рядом, но это не литература

Отдельный класс источников, нужный именно юридическим работам:

* **publication.pravo.gov.ru** — официальный портал правовых актов.
  Отвечает (`/api/PublicBlocks` → 200), но требует разбора формата.
  Полезен для точных реквизитов НПА;
* **sudact.ru** — судебная практика, отвечает, но только HTML: нужен
  парсер;
* **consultant.ru** — уже используется, но не как поставщик литературы:
  из него берутся оглавления кодексов для сверки ссылок на статьи.

Это не научная литература, и в список литературы они идут отдельными
разделами. Подключать их имеет смысл вместе с задачей «список
литературы по ГОСТ», а не сейчас.

## Как устроено в коде

Каждая база — отдельный модуль в `app/modules/sources/` с одинаковым
видом функции `find_sources(query, directions, min_year, limit)`,
возвращающей общий `Source`. Реестр `registry.py` опрашивает их
параллельно, сливает по нормализованному заголовку, ранжирует общим
ключом и придерживает пару мест для баз, проигравших по релевантности —
иначе русскоязычные заголовки вытесняют всё остальное подчистую.

Отказ любой базы не роняет поиск, но **обязательно пишется в лог**.
Молчаливый ноль неотличим от честного «по теме ничего не написано» —
именно так OpenAlex полгода выглядел работающим, не отдавая ничего.

## Откуда берутся данные для списка литературы по ГОСТ

Запись вида «Рябов, С. И. Некоторые проблемы пробелов и коллизий в
праве / С. И. Рябов, В. А. Поляков // Право и управление. – 2024. –
№ 9. – С. 301–304.» требует того, чего нет в обычной поисковой выдаче:
номера выпуска и страниц.

Собираются они так:

| Откуда | Что даёт | Покрытие на живой выборке |
| --- | --- | --- |
| мета-теги страницы статьи КиберЛенинки | страницы, номер, ISSN, издатель | 5 из 5 |
| поля Crossref (`page`, `volume`, `issue`, `ISSN`) | всё сразу | 2 из 2 |
| добор по DOI из текста статьи КиберЛенинки | остаток | 1 из 24 |

Последняя строка объясняет, почему основным способом стали мета-теги, а
не DOI: DOI в тексте статьи находится лишь у четверти записей, и добрая
половина этих DOI в Crossref не депонирована (404) — российские журналы
нередко регистрируют их в других агентствах.

На запросе «коллизии в праве способы разрешения» страницы известны у
**7 записей из 8**, список собирается за 2,8 секунды.

Чего нет в метаданных, того нет и в записи: выдуманный диапазон страниц
хуже отсутствующего, потому что выглядит достоверно и разваливается
при первой же проверке.

## Google Scholar: почему не подключаем

Проверено вживую 25 сентября 2026 года. Вопрос не в том, получится ли
технически — получается. Вопрос в том, что мы за это платим и что
получаем взамен.

### Официального API нет

У Google Scholar нет и никогда не было публичного API. Единственный
способ — разбирать HTML поисковой выдачи.

### robots.txt запрещает это прямым текстом

```
User-agent: *
Disallow: /search
Disallow: /scholar
Disallow: /citations?
```

`/scholar` — это ровно тот адрес, по которому идёт поиск. Запрет
распространяется на всех роботов без исключений: отдельные разрешения
есть только для Twitterbot и facebookexternalhit.

Наш сервис берёт с пользователей деньги. Строить платную функцию на
прямом нарушении robots.txt и пользовательского соглашения Google —
риск, который не окупается: доступ отключат в одностороннем порядке и
без предупреждения, причём в самый неподходящий момент.

### Технически сейчас работает — и это обманчиво

Шесть запросов подряд из рабочего окружения прошли: HTTP 200, по десять
результатов, без капчи. Но это поведение одного адреса с редкими
запросами. В продакшне запросы всех пользователей идут с одного IP
сервера, и Google показывает капчу — это известная и повсеместная
практика. Обходят её платными прокси-пулами, то есть деньгами, которые
разумнее потратить на что-нибудь полезное.

### Главное: данные там хуже наших

Вот что реально отдаёт выдача по запросу «коллизии в праве»:

| Поле | Что пришло |
| --- | --- |
| заголовок | `[ЦИТИРОВАНИЕ][C] Коллизии в праве: причины, виды и способы разрешения` |
| метаданные | `НИ Матузов - Известия высших учебных …, 2000 - … учреждение высшего образования …` |

Всё в одной строке, и эта строка **обрезана многоточиями**: название
журнала не восстановить. Инициалы слиты («НИ Матузов»). Нет страниц,
нет тома, нет номера выпуска, нет DOI, нет аннотации. Для
библиографической записи по ГОСТ этого не хватает принципиально:
получилось бы то самое неполное описание, которое возвращает
нормоконтроль.

Сравните с тем, что уже есть: КиберЛенинка даёт полный текст и через
мета-теги страницы — страницы и номер; Crossref — DOI, том, выпуск и
ISSN.

### И он ищет там же, где мы

Третий результат той же выдачи ведёт на `cyberleninka.ru`. Google
Scholar — агрегатор: он индексирует КиберЛенинку, eLibrary, репозитории
вузов и Crossref. Мы ходим в эти источники напрямую и получаем
структурированные метаданные вместо обрезанной строки.

### Если Scholar всё же понадобится

Законный путь один — платные посредники с собственными договорённостями
и прокси (SerpAPI и подобные, порядка 75 долларов в месяц за небольшой
объём). Смысл появится, если понадобится **индекс цитирований** по
русским работам: вот его у нас действительно нет, а Scholar считает
цитирования шире всех. Для подбора литературы и списка по ГОСТ — не
нужен.

**Вывод: не подключаем.** Запрещено правилами, ненадёжно в продакшне и
даёт данные хуже тех, что мы уже получаем бесплатно и легально.
