# Загрузка источников пользователем

Пользователь открывает настройки перед генерацией и прикладывает свои
файлы: методичку и статьи, на которые нужно опереться. Форматы — PDF,
DOCX, TXT, MD, RTF.

## Зачем

Автопоиск покрывает не всё, и мы это уже измерили: по узкой теме он
честно сообщает, что релевантных работ нет. Плюс научный руководитель
часто выдаёт список обязательной литературы — такие источники нельзя
ни найти автоматически, ни проигнорировать.

## Приоритет

Загруженные источники идут первыми и **не вытесняются** найденными
автоматически. Отбор по релевантности их не касается: пользователь уже
решил, что эти работы нужны. Если он загрузил больше лимита — берём
все, потому что молча выбрасывать выбранное нельзя.

## Эндпоинты

```
POST /api/v1/projects/upload/sources     файлы + необязательные названия
  → {accepted: [...], rejected: [{filename, reason}], total_chars}

POST /api/v1/projects/upload/methodichka  один файл
  → {text, found: [{field, value, quote, confidence}], report}

POST /api/v1/ai/analyze-topic/grounded
  {"topic": "...", "uploaded_sources": [{"text": "...", "title": "..."}]}
```

Файлы разбираются независимо: ошибка в одном не отменяет остальные.
Пользователь видит, что принято и что нет, с причиной по каждому отказу.

## Что вскрыли реальные файлы

Синтетические тесты проходили, а семь настоящих PDF показали три
дефекта. Все они относятся к одному классу: **документ — это не только
текст статьи, у него есть служебная обёртка.**

### Титульный лист вместо заголовка

Магистерская диссертация дала заголовок «МОСКОВСКИЙ
ФИНАНСОВО-ЮРИДИЧЕСКИЙ УНИВЕРСИТЕТ». Первая содержательная строка файла
— название вуза, а тема работы идёт ниже, после маркера «на тему:».

Порядок распознавания теперь такой:

1. маркер «на тему:» / «Тема:» — следующая строка и есть название
2. строка целиком в кавычках (с обеих сторон)
3. блок строк капслоком, склеенный по переносам
4. первая содержательная строка
5. имя файла

Отдельно отсеиваются: названия вузов и кафедр, грифы «допустить к
защите», строки-бланки с подчёркиваниями, «(подпись)», «(Ф.И.О.)»,
и ФИО целиком капсом — на титуле диссертации это автор, не заголовок.

### Заглушка бланка вместо автора

Автором становилось «И.О. Фамилия» — образец заполнения из шаблона
титульного листа. Такие заглушки отсеиваются отдельным правилом.

### Титульник и оглавление в промпте

Самое серьёзное. Диссертация на 187 тысяч знаков дала **ноль тезисов**:
в промпт уходили первые 3500 знаков файла, то есть название вуза,
подписи и оглавление с номерами страниц. Модель добросовестно
прочитала список глав и не нашла там ни одной мысли.

Теперь для загруженных документов берётся содержательный фрагмент:
поиск начинается от «ВВЕДЕНИЕ» или от конца оглавления, строки вида
«1.2. Название ....... 15» выбрасываются.

После правки тот же файл дал тезис по существу, а число выявленных
научных споров выросло с 0 до 2.

## Прочее

- Кодировка текстовых файлов определяется по доле кириллицы: CP1251
  встречается не реже UTF-8 у файлов из старого Word.
- Скан без текстового слоя отклоняется с внятным объяснением, а не
  молча даёт пустой источник.
- `.doc` (старый бинарный формат) отклоняется с советом пересохранить
  в `.docx`.
- Из DOCX забираются и таблицы: в них часто судебная статистика.

## Чего пока нет

Файлы разбираются в памяти и не сохраняются: postоянное хранение — это
модуль Projects на PostgreSQL, он ещё не начат. Сейчас фронтенд должен
передать текст обратно в `analyze-topic/grounded`.
