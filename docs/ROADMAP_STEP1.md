# Порядок работы: от каркаса к рабочему сервису

Принцип: каждый шаг заканчивается **чем-то запускаемым**, а не «написали ещё
пять файлов». После каждого шага можно остановиться и не остаться с руинами.

---

## Шаг 0 — Фундамент (можно начинать хоть сейчас, данных не требует)

**Что делаю:**
- `docker-compose.yml`: PostgreSQL, Redis, ChromaDB, backend.
- Скелет FastAPI по структуре модулей из ТЗ (`app/modules/*`), с
  заглушками-интерфейсами — границы модулей зафиксированы сразу.
- `config.py` на pydantic-settings, `models.yaml` для AI Router.
- SQLAlchemy-модели: `users`, `projects`, `project_sections`, `sources`,
  `transactions` — ровно по вашей схеме БД.
- Alembic-миграции.
- `/api/v1/health` — чтобы было видно, что всё поднялось.

**Результат:** `docker compose up` → живое окружение, БД с таблицами.
**Нужно от вас:** ничего.

---

## Шаг 1 — AI Engine + пайплайн «Анализ → План»

**Что делаю:**
- `ModelRouter` с приоритетами из `models.yaml` и fallback (переношу
  рабочую логику из Node-ветки, дополняю логированием успешности моделей).
- `PromptBuilder`, промпты переезжают из `api/prompts.js`.
- Эндпоинты `POST /api/v1/projects` и запуск этапов `analysis`, `plan`.
- SSE-стриминг прогресса.

**Результат:** через API можно завести проект по теме и получить
`analysis.md` + `plan.md`, сохранённые в БД.
**Нужно от вас:** ключ OpenRouter. Желательно — ваш промпт по курсовой.

---

## Шаг 2 — Documents (интеграция вашего кода ГОСТ)

**Что делаю:**
- Оборачиваю ваш генератор в модуль `documents/` с чистым интерфейсом.
- Сборка Markdown-секций из БД → DOCX. PDF-конвертер.
- `GET /api/v1/documents/download/{project_id}`, файловое хранилище.

**Результат:** скачивается настоящий .docx по ГОСТ.
**Нужно от вас:** код ГОСТ + пример эталонного .docx.

---

## Шаг 3 — Task Queue + генерация глав

**Что делаю:**
- Celery + Redis, задачи `generate_project_task`, посекционная генерация.
- Прогресс через WebSocket/SSE, статусы проекта.

**Результат:** запустил генерацию — работа пишется в фоне, прогресс виден.
**Нужно от вас:** ваше видение поэтапного создания работы + промпты этапов.

---

## Шаг 4 — RAG + стиль Коколова

**Что делаю:**
- ChromaDB, коллекции `style_kokolov`, `sources_verified`, `gost_rules`,
  `examples_good`, `user_project_{id}`.
- Ингестия Markdown, разбор ваших текстов → извлечение правил стиля →
  `kokolov_style.json` на ваше утверждение.
- Подмешивание контекста стиля в промпты.

**Нужно от вас:** 5–10 текстов Коколова.

---

## Шаг 5 — Humanizer + ИИ-детектор

**Что делаю:**
- Алгоритмы: детекция повторов конструкций, варьирование ритма, замена клише.
- Интеграция вашего детектора, цикл «переписать, пока score выше порога».

**Нужно от вас:** код детектора + порог + примеры для тестов.

---

## Шаг 6 — Sources & Verification

Парсеры CyberLeninka / eLibrary / сайты судов, проверка URL и DOI через
CrossRef, флаг `is_verified`, сборка библиографии. Только verified идут в список.

---

## Шаг 7 — Users & Auth, Payments

JWT-авторизация, личный кабинет, история работ. ЮKassa: счета, вебхуки,
разблокировка платных функций. Rate limiting, капча, дисклеймеры.

---

## Шаг 8 — Frontend Vue 3

Перенос 16 ретро-тем в Vue 3 + TS: темы становятся наборами CSS-переменных,
визард создания работы, прогресс-бар в стиле загрузки BIOS, история, оплата.

---

## Оценка

Шаги 0–2 — обозримый и полезный первый результат: рабочее окружение,
генерация анализа и плана, выгрузка в DOCX по вашему ГОСТ. Это уже
демонстрируемый продукт.

Шаги 3–8 — существенно больше по объёму, идут итерациями по мере
поступления ваших материалов.
