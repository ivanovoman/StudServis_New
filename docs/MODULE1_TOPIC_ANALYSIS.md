# Модуль 1: анализ темы

`backend/app/modules/ai_engine/topic_analysis.py`,
API — `POST /api/v1/ai/analyze-topic`, 36 тестов.

Первый этап конвейера и единственный, который увидят все: он
бесплатный и лимитами не ограничивается.

## Главное решение: структурированный выход вместо заметок

Промпт в `api/prompts.js` просил «структурированные заметки (черновик
мышления)». Свободный текст не проверить автоматически и не передать
дальше: план работы должен строиться на тезисах анализа, а выцарапывать
их регулярками из прозы — источник ошибок.

Теперь модель обязана вернуть JSON:

```json
{
  "core": "в чём суть темы, одно предложение",
  "theses": ["ключевые утверждения, которые работа раскроет"],
  "logic_arc": ["в каком порядке раскрывать и почему"],
  "controversies": ["где реальные разногласия судов и доктрины"],
  "banality_risks": ["куда скатываются слабые работы по теме"],
  "search_directions": ["что искать в источниках"]
}
```

Парсер терпим к реальному поведению моделей: снимает обёртки из
тройных кавычек, находит первый сбалансированный объект среди
пояснений, корректно проходит скобки и экранированные кавычки внутри
строк, принимает строку там, где ожидался список.

## Защита от выдуманной фактуры

Это ключевая проверка этапа. Ранние прогоны показали, что модель
уверенно выдумывает юридические реквизиты: «ст. 61.2» вместо 61.10,
дело №А40-15002/2019 с несуществующими фирмами, «ФЗ №208-ФЗ
„О несостоятельности“» (208-ФЗ — об АО).

На этапе анализа RAG и проверки источников ещё нет, поэтому правило
такое: **модель описывает, что искать, а не называет реквизиты.**

- ✗ «дело № А40-1234/2022» → ✓ «практика окружных судов за последние 3 года»
- ✗ «ст. 61.10» → ✓ «нормы о контролирующих лицах в законе о банкротстве»
- ✓ ГК РФ, УК РФ — общеизвестные кодексы называть можно

Всё, что похоже на точный номер дела, статьи, закона или сумму, —
брак с требованием переформулировать.

### Защита проверена в бою

Я специально прогнал этап с промптом БЕЗ запрета на реквизиты. Модель
немедленно выдала:

```
дела:   № А40-207995, № А40-294891, № А40-142113, № А40-127923
статьи: ст. 61, ст. 10
законы: № 127-ФЗ, № 266-ФЗ, № 555-ФЗ

```

`№ 555-ФЗ` почти наверняка не существует. Проверка отбраковала ответ
по всем четырём категориям — то есть защита не декоративная.

## Живое тестирование

7 прогонов на реальных моделях, включая темы-ловушки, где особенно
тянет выдумать реквизиты:

| Тема | Тезисов | Направлений | Проверка |
|---|---|---|---|
| Субсидиарная ответственность | 7 | 8 | прошла |
| Оспаривание сделок в банкротстве | 7 | 8 | прошла |
| Компенсация за товарный знак | 7 | 8 | прошла |
| Ответственность за налоговые правонарушения | 7 | 8 | прошла |
| Налоговое планирование в малом бизнесе | 7 | 8 | прошла |
| Бизнес-модель IT-стартапа | 6 | 8 | прошла |
| Открытие кофейни | 7 | 8 | прошла |

**7 из 7**, ни одной выдуманной ссылки.

Предмет влияет на промпт: для юридической работы просим нормы и
практику, для экономической явно говорим «не навязывай ссылки на нормы,
если тема их не требует». Это следствие замера: у автора в юридической
работе ссылок 4.67 на 1000 слов, в экономической 0.04.

## Что проверяется помимо фактуры

- ядро темы сформулировано и не куцее;
- тезисов 3–7, каждый — утверждение, а не заголовок раздела
  («Понятие контроля» — брак, это название параграфа);
- нет дубликатов тезисов;
- логическая дуга описана;
- направлений поиска не меньше пяти;
- указаны риски банальности (предупреждение).

Превышение 7 тезисов — предупреждение, а не брак: сложная тема может
требовать больше, это ваше решение «зависит от темы».

## Поведение при сбоях

- модель вернула не-JSON → HTTP 502 с понятным текстом;
- все модели недоступны → HTTP 502;
- проверка не пройдена → HTTP 200, анализ **всё равно отдаётся**
  вместе со списком претензий. Пользователь видит и результат, и что
  с ним не так.
