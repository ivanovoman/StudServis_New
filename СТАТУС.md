## Работает целиком

### Генерация текста

* **GigaChat — основной провайдер**, OpenRouter (только бесплатные
  модели) — запасной, переключение автоматическое. Полная сборка работы
  «Коллизии в праве» из шести частей заняла 1 час 40 минут и дала
  29 720 знаков без единого испорченного символа.
* **12 промптов** по шагам: анализ темы, план, введение, план раздела,
  написание, расширение, шлифовка, таблица, проверка таблицы,
  заключение, общая правка, речь для защиты.
* Объёмы заданы так, как вы просили: введение 3800–5000 знаков без
  пробелов, раздел 5000–6000.
* Если раздел вышел коротким, он **дописывается автоматически** —
  не больше двух попыток, чтобы не растекаться.

### Подбор литературы

* **Четыре базы разом**: КиберЛенинка, Crossref, OpenAlex, DOAJ. Все
  бесплатные, все Open Access. Если одна молчит, работают остальные, и
  это видно в логе.
* Малым базам резервируются места в выдаче, иначе КиберЛенинка
  вытесняет всех.
* Для верхних статей догружается **полный текст** — модель пишет по
  нему, а не по названию.

### Список литературы по ГОСТ

* Запись по **ГОСТ Р 7.0.100-2018**: тире вместо дефиса, фамилия
  инвертирована в начале и прямая после косой черты, «[и др.]» после
  трёх авторов, дата обращения у электронных ресурсов.
* Страницы и номер выпуска берутся из мета-тегов страницы статьи —
  на живой выборке известны у **7 записей из 8**.
* Список **сам попадает в .docx** отдельным разделом, строка на него —
  в содержании.
* Чего нет в метаданных, того нет и в записи: выдуманный диапазон
  страниц хуже пустого, он выглядит достоверно.

### Проверка ссылок на закон

* Прямо во время сборки текст сверяется с 14 кодексами на
  consultant.ru. Статусы: `ok`, `missing`, `mismatch`, `listed`,
  `unclear`, `unknown`.
* Несовпадение отмечается, только если нашлась более подходящая статья
  того же кодекса либо статья утратила силу — иначе будет много шума.
* Понадобилось потому, что **модели OpenRouter систематически
  выдумывают номера статей**. У GigaChat такого не замечено.

### Документ по ГОСТ

* Поля страницы, шрифт, полуторный интервал, абзацный отступ,
  нумерация. Разделы: СОДЕРЖАНИЕ, ВВЕДЕНИЕ, главы с разделами,
  ЗАКЛЮЧЕНИЕ, СПИСОК ЛИТЕРАТУРЫ.
* Таблицы с подписями и ссылкой из текста.
* Экспорт одного фрагмента и работы целиком.

### Настройки до генерации

* Тема, вуз, **методичка**, пожелания, число глав (2 или 3), источники.
* Приоритет: умолчания → пресет → методичка → ваши пожелания → явный
  выбор.
* Клише — «не выше авторского уровня»; таблицы, графики и судебные
  кейсы — там, где уместны, а не по разнарядке.

### Хранение работ

* Таблицы `works` и `work_pieces`, статусы `draft`/`assembling`/`done`.
* Доступ по ключу владельца, БД — SQLite или PostgreSQL по настройке.

### Интерфейс

* **16 ретро-тем**, у всех одинаковое меню из 8 пунктов и кнопка
  настроек.
* Прогресс сборки идёт потоком (SSE): план, предупреждения, готовые
  части, проверка ссылок на закон, итог.

### Детектор ИИ-текста

* Ваш алгоритм, без сторонних сервисов. AUC 0.893 после того, как
  научился снимать markdown-разметку: без этого сравнение текстов из
  PDF и из API давало бессмысленные 0.375.

## Ещё не начато

* **Оплата через ЮKassa** — нужны реквизиты магазина.
* **Vue 3 + TypeScript** — интерфейс пока на чистом JS без сборки.
* **PostgreSQL** как основная БД (сейчас SQLite).
* **Qdrant и RAG** — векторного поиска нет ни в каком виде.
* **Celery и очереди** — задачи выполняются прямо в запросе.
* **Регистрация и вход** — пользователей как таковых нет.
* **Анти-бот защита**, дисклеймеры в интерфейсе.
